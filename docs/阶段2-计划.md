## 2. 架构

```
apps/server/        NestJS 12 + Prisma 7 + MySQL 8
  auth              登录方式可插拔：网页（见第 4 节待确认 1）、小程序 wx.login、开发登录（仅开发环境）
                    令牌：短期 access token（JWT，2 小时）+ 长期 refresh token（存库、可吊销，30 天）
  users             昵称、头像、注销账号（删除全部数据）
  works             作品 CRUD；乐观并发（revision 号，冲突时不覆盖、另存一份）；历史版本
  palettes          色卡下发（带版本号，客户端缓存；服务端不可用时客户端用内置色卡）
  files             原图、缩略图：存储接口抽象，本阶段存本机磁盘，上线换腾讯云 COS
  admin             管理员账号（独立于用户，密码 + 角色），色卡编辑、用户查询
apps/admin/         Vue 3 + Element Plus + Vite
docker-compose.yml  本机开发用 MySQL 8
```

- **作品数据格式**：沿用 `@pd/editor-core` 的 `PatternDraftV1`（网页、小程序、后端三处同一格式），服务端只校验、不解释格子内容。
- **历史版本**：自动保存只更新当前版本；每次「重新生成前自动备份」、手动「保存版本」、或距上一个版本超过 30 分钟的保存，才新增一个历史版本；每个作品最多保留 30 个，超出删最旧的。
- **同步规则**：本机 IndexedDB 仍是主存储（离线可用）；登录后每次本机保存都排队上传；打开「我的作品」时合并云端列表。两端同时改同一作品时，后保存的一方收到冲突，自动另存为「xxx（冲突副本）」，不丢任何一方的修改。
- **安全**：密码用 argon2 / bcrypt 哈希；登录、发送验证码接口限流；所有作品接口按用户隔离；上传文件限类型和大小；后台接口单独鉴权；`.env` 不入库，提供 `.env.example`。
- **AGPL**：网页和后台页面底部加源码地址（AGPL 第 13 条，阶段 1a 的遗留项一并做掉）。

## 4. 待确认

1. **网页登录方式**（影响最大）：
   - 推荐：**用户名 + 密码**——不依赖任何外部服务，本机就能完整测试；小程序上线后再加「网页显示小程序码、微信扫码登录」，并支持把两边账号绑定。
   - 备选 A：手机号 + 短信验证码——中国用户最习惯，但要开通云短信（按条收费，签名需要营业执照或已上线的小程序 / 公众号）。
   - 备选 B：只做小程序扫码登录——要等小程序有正式 AppID 并发布体验版，在那之前网页无法登录。
2. **运行环境**：本阶段只在本机跑（推荐），不买服务器、不部署。
3. **文件存储**：本阶段存本机磁盘（推荐），上线时换腾讯云 COS。

## 5. 风险

**你来验收时可以这样试**（需要 Docker）：
1. `pnpm db:up` → `pnpm --filter @pd/server db:deploy` → `pnpm dev:server`，另开终端 `pnpm dev:web`。
2. 网页右上角「登录」→ 注册 → 做一张图纸；换一个浏览器（或无痕窗口）登录同一账号，「我的作品」里能看到并继续编辑；回到第一个浏览器，作品会自动载入新版本。
3. 两边同时改同一张图纸：会多出一个「（冲突副本）」，两边的修改都在。
4. 顶栏「历史版本」：存一个版本、改几笔、恢复。
5. `pnpm --filter @pd/server admin:create 你的用户名` 建管理员 → `pnpm dev:admin` 打开 http://localhost:5174 → 改一个颜色的色值并发布 → 网页刷新后生效（记得改回来）。
