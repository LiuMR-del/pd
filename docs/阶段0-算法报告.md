> **2026-10-30 更新（方案 v0.5）**：新增细笔画保护、边缘归并、主体撑满网格，默认取色从 k=3 改为 k=1。最新数据和结论见 **第 4.8 节**，它优先于下表和第 4.1~4.7 节（那些是 v0.4 的数据，保留作记录）。v0.5 下：同 221 色板对比，CAM16 我们 7.00 / 6.76，豆格 7.37，今天拼豆了吗（复刻）7.73；暗线召回我们 86.4%，豆格 83.4%，已反超；细节召回约为两家的 2 倍。
>
> **2026-11-03 更新（色卡纠正）**：MARD 色号去前导零、色数档换成真实套装、85 个色值换成 MARD拼豆助手的数据（见 `docs/色号调研.md`）。重跑结果见 **第 4.9 节**：推荐配置 CAM16 卡通 7.11 → 7.02、照片 6.78 → 6.72，暗线召回 +1.1~1.3 个百分点，去背景指标不变，结论和推荐参数都不变。

| 问题 | 结论 |
|---|---|
| 色差公式 Oklab 还是 CIEDE2000 | **CIEDE2000，配合 Oklab 预筛 K=8 个候选**（`metric: 'ciede2000', prefilterK: 8`）。用中立指标 CAM16-UCS 评判，它在 8 类 × 2 预设共 16 组对比中全部优于或等于 Oklab（v0.4；v0.5 下为 15/16 组，见第 4.8 节），速度比精确 CIEDE2000 快约 1.5 倍。Oklab 留作低端机降级选项。理由见第 4 节 |
| 我们的管线 vs perler-beads 原版 | 原版默认参数会把整张图合并到只剩约 3 种颜色（原因见 3.1），CAM16 色差是我们的约 2 倍。关闭原版的合并后，与我们相比：色差接近，但用色是我们的 2.6~4.5 倍，孤立单颗约是我们的 35 倍，几乎没法拼 |
| 性能 | 100×100 网格、MARD 72 色：推荐配置 41~80ms；全 291 色时 82~165ms（v0.4）。v0.5 加入细笔画检测后为 82~137ms / 107~176ms。都远低于 1s 的目标 |
| 去背景 | 合成图上主体误删率为 0%（v0.4；v0.5 推荐配置 ≤0.25%，Oklab ≤1.0%）（原版：渐变底 89%、主体触边 16%）；背景残留 ≤ 1.4%（v0.5 ≤5.9%，残留的是主体细描边，见第 8 节第 13 条） |
| 竞品 | 5 张图、72 格、24 色。CAM16 平均：豆格 7.37，今天拼豆了吗（本地复刻、近似）7.73；我们用同一 221 色板时 6.20~6.47，用 291 色时 5.85~6.07。孤立单颗：我们 0.3~0.4%，两家 2.3~3.7%。**两家的暗线召回和细字清晰度都比我们好（82~83% 对 75~81%）**，这是我们要追的短板 |
| 像素图 | 整数倍放大的像素图能精确对齐（周期 6、零误差还原）；YouTube 缩略图这类非整数缩放的像素图检测不到周期，自动退回普通网格（已知问题） |

## 2. 实现范围

- `packages/pattern-core`：纯 TS、零运行时依赖。`tsconfig` 的 `lib` 只开 ES2020、不含 DOM，编译期就能拦住 DOM 和 Canvas 用法。
  - 色彩转换：sRGB / 线性 / XYZ / Lab / Oklab。
  - CIEDE2000：Sharma 2005 的 34 组测试数据全部通过，误差 < 5e-5。
  - 可插拔距离：`oklab` / `ciede2000`，后者可加 Oklab 预筛。
  - 色板预计算：按色板签名缓存；最近色查询用亮度下界剪枝，并按量化后的查询色缓存。
  - 线性光空间区域平均重采样、宽高比网格、整数像素周期检测。
  - 单格 k×k 投票，含中心加权和暗线保护。
  - 限色：Ward 式加权贪心合并、显著色保护，外加一轮限定在色板内的 k-means 精修。
  - Lab 误差扩散抖动。
  - 后处理：孤立点、小色块、去背景、裁边。
  - 预设：3 种风格 × 3 档尺寸。
  - baseline：perler-beads 原版管线。
  - 编辑工具：perler-beads 编辑函数移植。
- `packages/palettes`：perler-beads 的 291 色 × 5 品牌色卡，转换成我们的 JSON 结构，配校验脚本和单测。
- `tools/bench`：程序生成的合成图、指标、预览图、总览图、静态对比页，以及参数扫描、性能测试、预筛一致率测试。

## 3. 评测方法

- **测试集**：22 张真实图（7 类，CC BY，见 `tools/bench/images/manifest.csv`），外加 9 张程序生成的合成图：色块、渐变、细线、点阵字、白底主体、渐变底主体、主体触边、原生像素图、6 倍放大像素图。其中 4 张带真值掩码（另有 1 张像素图同时带掩码）。
- **主矩阵**：色板 MARD 全 291 色；均衡档（长边 72 格，上限 24 色）；卡通 / 照片两种预设。

| 组别 | 说明 |
|---|---|
| baseline | perler-beads 原版：卡通 = dominant，照片 = average，相似色阈值 30（原版默认） |
| baseline-nomerge | 同上，但关闭相似色合并（公平对照） |
| ours-oklab | 我们的管线 + Oklab |
| ours-ciede2000 | 我们的管线 + 精确 CIEDE2000 |
| ours-ciede2000-k8 | 我们的管线 + CIEDE2000 + Oklab 预筛 8 个候选（推荐默认） |

- **指标**：参考值 = 原图在同一网格上做线性光区域平均的结果。

| 指标 | 含义 |
|---|---|
| ΔE00 | 每颗豆与参考格的 CIEDE2000 色差均值。**天然偏向 CIEDE2000 组** |
| ΔEok | Oklab 欧氏距离 ×100 的均值。**天然偏向 Oklab 组** |
| ΔE CAM16 | CAM16-UCS 色差均值。与两种匹配公式都无关，作为两组之间的**中立裁判** |
| 平滑 ΔE00 | 图纸与参考都做 3×3 平滑后再比，抖动结果「整体对就行」时可以得分 |
| 用色数 | 图纸实际用到的颜色数 |
| 孤立单颗 | 8 邻域内没有同色豆的格子占比 |
| 暗线召回 | 含暗线的格子（其子采样最暗 L* < 25）中，被画成深色（L* < 35）的比例 |
| 主体误删 / 背景残留 | 只在带掩码的合成图上计算 |
| 耗时 | 生成一张图纸的毫秒数 |

- **指标局限**：参考值是「格内平均色」，所以凡是追求边缘干净、不出现混合色的手段（投票、暗线保护），ΔE 都会变差。这类改动要结合暗线召回和对比页来判断。

### 3.1 关于 baseline 只用约 3 种颜色

perler-beads 在 2026-04-08 的提交 `ba83fbd`（「使用LAB空间距离」）中，把颜色距离从 RGB 欧氏距离（0~441）改成 Oklab×100（黑白距离为 100），但默认合并阈值仍是 30。新量纲下 30 相当于全量程的 30%，所以 commit `2efee730` 的默认参数会把大部分颜色合并掉。我们的 baseline 是对它的忠实移植，并有单测验证。为了公平，另设了 baseline-nomerge 组。

### 4.6 Oklab 预筛 K 个候选与精确 CIEDE2000 的一致率

查询集：22 张真实图按 216 列做线性平均后的全部像素，共 692,928 个颜色。

| 色板 | K | 结果一致率 | 平均 ΔE00 损失 | 最大损失 | 耗时（精确 → 预筛） |

| 72 | 16 | 99.93% | 0.0004 | 2.10 | 1031 → 1195ms |

**复刻出的默认管线**（网页端，「混合」算法 + 卡通模式，72 格、24 色）：
1. 长边缩到 1024 以内。
2. 自动裁掉近白或透明的边缘，四周各留「长边 / 72」的余量。
3. 5×5 保边平滑。
4. 每格只取**中心 1 个像素**。
5. 从四边洪泛近白格作为背景。
6. CIEDE2000 匹配，色板为 MARD 221 色。
7. 限色三步，24 色对应 balanced 档：
   - ΔE76 ≤ 7.5 的相近色两两合并，直到剩 20 色；
   - 少于 12 格的稀有色，并入 ΔE ≤ 18 以内的最近色；
   - 最后强制合并到 24 色。
8. 主体外的格子和背景都写成 H02 白豆。
9. 生成后一定执行一次近色孤岛降噪：同色块最多 4 格，邻域支撑 ≥ 4，ΔE76 ≤ 28（强支撑时放宽到 42），共 3 轮，带肤色保护。

**与真实输出的差异**（结果只能视为近似）：
- 浏览器的高质量缩放，用 sRGB 空间区域平均来近似；
- 没有模拟上传页可能做的白底重绘和 JPEG 压缩；
- 「柔和」算法和小程序端分支没有复刻。

### 4.8 v0.5 改进：细笔画保护、k=1、边缘归并、主体撑满（2026-10-30）

数据来自 2026-10-30T06:48Z 的 `pnpm bench`（同一台机器）。

**动机**：第 4.7 节显示，细线和细字是我们唯一落后于两家的地方。根因是先把每格平均成 3×3 个子采样点再判断：一条只占格宽 1/5 的笔画，在子采样点里只剩一点灰，投票和暗线保护都看不到它。两家都是直接在原图像素上判断（今天拼豆了吗每格取中心 1 个像素，豆格逐像素投票），所以线条更「硬」。

**改动**（代码在 `packages/pattern-core/src/sample/stroke.ts`、`sample/edgeSnap.ts`、`pipeline.ts`）：

1. **细笔画保护**：在每格最多 8×8 的细网格上，对亮度 L* 做形态学 top-hat（窗口约一格宽），找出比一格还细的深线（black top-hat）和浅线（white top-hat）。某格内笔画像素 ≥10%、对比 ≥25 L* 时，用笔画核心的颜色覆盖该格。两道上下文条件防误判：
   - 周围 7×7 格内与笔画同色调的像素 ≤35%。否则说明这条「细线」其实是深色底上白字之间的缝（Kampana 标题曾因此被切碎）；
   - 周围笔画像素密度 ≤25%。否则是密集纹理（如细条纹），不是单独的线条。
2. **默认 k=1**：有了第 1 步，k=3 投票已经没有必要。k=1（每格线性光平均）在 8 类图上的 CAM16 全部更好，还能保住白底主体的眼睛高光、深蓝底「HELLO」的 H（第 8 节第 2 条已解决）。
3. **边缘归并（仅卡通预设）**：k=1 的副作用是硬边上的格子会取到两侧颜色的混合色，例如白底主体外一圈浅灰，去背景也去不掉。规则：格内 3×3 子采样的色差 ≥40（格内确实有一条硬边），且平均色落在两侧邻格颜色的线性光连线上，就归到更接近的一侧。平滑渐变的格子内部是均匀的，不受影响。
4. **主体撑满网格**（`fitSubject`，开启去背景时生效）：先跑一遍，得到主体外框后，再按外框重新生成一次，让主体用满用户选的长边。借鉴自今天拼豆了吗。耗时约翻倍，只在去背景时触发。

**评测新增「细节召回（暗 / 亮）」**：在每格 8×8 的细网格上统计，独立于 k×k 平均。某格 6%~50% 的细像素比该格 75 分位亮度暗 ≥30 L*，算一个「暗细节格」；豆子比该分位暗 ≥15 L* 算召回。亮细节对称处理。大色块的边缘两侧都会计入，所以把一种色调加粗会降低另一种的召回。

## 6. 最终推荐：CIEDE2000（+ Oklab 预筛 K=8）

1. **中立指标支持 CIEDE2000**：CAM16-UCS 与两种匹配公式都无关。按它评判，在 8 类 × 2 预设共 16 组对比中，推荐配置全部优于或等于 Oklab（v0.4 数据；v0.5 下 AI 图卡通预设是唯一例外，见第 4.8 节）（差距最小的是合成图 4.30 对 4.33、AI 图照片预设 8.64 对 8.68）。全体平均比 Oklab 低约 3.5%（卡通 6.88 对 7.14，照片 6.45 对 6.68）。精确 CIEDE2000 与推荐配置之间互有高低，差距 ≤ 0.25。
2. **视觉上可以接受**：精确 CIEDE2000 在深蓝、天空等大色差处会选更饱和的颜色（第 4.6 节），加 Oklab 预筛后这种倾向减轻，CAM16 也更好。
3. **性能足够**：推荐配置在 100×100 / 72 色时为 41~80ms（v0.4；v0.5 为 82~137ms），耗时是精确 CIEDE2000 的约 0.6~0.85 倍、Oklab 的约 3 倍，桌面端远低于 1s。
4. **Oklab 的定位**：最快（约 20ms），CAM16 只比推荐配置差约 3.5%。保留为「低端机 / 实时预览」的降级选项：拖动滑杆时用 Oklab 出预览，松手后用推荐配置出最终图纸。

## 8. 已知问题与待人工评审

1. **【v0.5 已定：k=1，见第 4.8 节】k=1（纯平均）与 k=3（投票）的取舍需要看图决定**：现有指标以「格内平均色」为参考，天然偏向平均。k=1 的 ΔE 明显更低，但暗线召回差 16 个百分点，边缘会出现大量过渡色。对比页里已加入 `ours-ciede2000-k8-k1 / cartoon` 列（全部图平均：CAM16 5.44 对 6.88，孤立单颗 0.14% 对 0.22%，暗线召回 73.1% 对 89.0%）。请对照 `ours-ciede2000-k8 / cartoon` 列，重点看卡通类和文字类的边缘观感。
2. **【v0.5 已解决：k=1 + 细笔画保护下「HELLO」的 H 完整】深色底上的浅色细笔画**：卡通预设下，深色背景（L* ≈ 18，接近暗线阈值 luma 45 对应的 L* 17.6）上约 1 格宽的浅色笔画，仍可能被暗线保护吞掉。已加入「邻域以浅色为主」和「必须紧贴浅色格」两道判断，有所改善但没有根除。临时办法：这类图用照片预设，或把 luma 调到 35（扫描显示暗线召回 88.4%、ΔE 更低）。
3. **真实像素图检测不到周期**：只支持整数倍放大。非整数缩放或经过 JPEG 压缩的像素图会退回普通网格。后续可以加小数周期搜索，或让用户手动指定格数。
4. **【v0.5 部分缓解：细笔画保护能保住覆盖 ≥10% 格宽的线】1px 细线丢失**：网格较粗时（每格约 9px），覆盖比例低于 30% 的线达不到暗线保护阈值。这是物理分辨率的限制，可以通过提高网格或降低 ratio 缓解。
5. **去背景规则依据不足**：「边缘连续段」规则是被合成图问题驱动加入的，真实去背景样本不足（只有 portrait_02 一张纯色底人像，没有掩码），需要补充带掩码的真实样本。
6. **色卡数据问题**（来自 perler-beads 原始数据，未修改）：

   - （2026-11-03）MARD 部分已纠正：色号去前导零，221 色色值改用本机下载的 MARD拼豆助手数据（见第 4.9 节）。其他 4 个品牌仍是上述情况。
