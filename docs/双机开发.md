# 双机开发（Mac + Windows）

> 2026-11-04 起两台电脑都会改代码，通过 GitHub（`origin/main`）同步。

## 1. 两台电脑的环境

| | Mac | Windows |
|---|---|---|
| 项目目录 | `/Users/liu/Downloads/tool/PD` | 按实际拷贝位置 |
| Node | nvm 管理，v24.16.0 | 便携版 v26.13.0，`C:\Data\Project\环境\node` |
| pnpm | 12.16.1（nvm 全局安装） | 12.16.1（装在上面的 node 目录） |
| Git | 系统自带，代理 `127.0.0.1:7890` | 便携版 2.56.0，`C:\Data\Project\环境\git` |
| PATH | 已配置，打开终端即可用 | 用户 PATH 已恢复成原样，每次开工先运行 `tools\env\win.cmd` |
| 仓库本地设置 | `core.fileMode=true`（默认） | `core.fileMode=false`（Windows 识别不到可执行位） |

两边 Node 主版本不同（24 / 26），`package.json` 要求 ≥ 20，两边单测都通过（Mac 2026-11-04、Windows 2026-11-03 各 142 个）。

### Windows 开工

```bat
:: cmd 窗口：运行一次，当前窗口里就能用 node / pnpm / git
tools\env\win.cmd

:: PowerShell：在命令前加脚本，一次运行一条
tools\env\win.cmd pnpm dev:web
```

工具不在 `C:\Data\Project\环境` 时，先 `set PD_ENV_DIR=实际目录`。脚本会沿用 `node_modules` 安装时的 pnpm store 位置，避免换 store 后重装整个依赖。

## 2. 每次换电脑的固定步骤

1. **开工前**：`git pull`。拉下来的提交改了 `pnpm-lock.yaml` 或某个 `package.json` 时，再运行 `pnpm install`。
2. **收工前**：提交并 `git push`，另一台才能拿到。没写完也可以先提交，在提交说明里写明「未完成」。
3. 两台不要同时改同一处。真的冲突了，按正常的 git 合并处理，不要强推。

## 3. 不同步的东西（每台电脑各自一份）

| 内容 | 位置 | 说明 |
|---|---|---|
| 依赖 | `node_modules/` | 每台各自 `pnpm install`，不能拷贝 |
| MARD 色值 | `packages/palettes/data/local/mard-hex.json` | 不入库（许可原因）；新电脑运行 `pnpm palettes:sync` 下载一次；两台目前都已有 |
| 色卡数据 | `packages/palettes/data/palettes.json` | `pnpm install` 时自动生成 |
| 评测输出 | `tools/bench/out/` | `pnpm bench` 生成 |
| 竞品截图 | `tools/bench/competitors/` | 不入库，只在当时做对比的那台电脑上 |
| 网页里的「我的作品」 | 浏览器 IndexedDB | 按电脑、浏览器、网址各存一份；无痕窗口关闭后会清空 |

## 4. 换行符和文件名

- 根目录 `.gitattributes` 规定仓库里一律存 LF（`.cmd` / `.bat` / `.ps1` 除外，存 CRLF），所以 Windows 上的 `core.autocrlf` 设置不会再造成整文件换行符变化。
- 第三方原样数据（`packages/palettes/vendor/`、`tools/bench/images/manifest.csv`）保持原来的 CRLF，不转换。
- 中文文件名两边都能正常用；在 Mac 上 `git status` 里中文显示成 `\350…` 转义只是显示问题，可以用 `git -c core.quotepath=false status` 看。
