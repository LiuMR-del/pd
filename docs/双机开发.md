### Windows 开工

```bat
:: cmd 窗口：运行一次，当前窗口里就能用 node / pnpm / git
tools\env\win.cmd

:: PowerShell：在命令前加脚本，一次运行一条
tools\env\win.cmd pnpm dev:web
```

工具不在 `C:\Data\Project\环境` 时，先 `set PD_ENV_DIR=实际目录`。脚本会沿用 `node_modules` 安装时的 pnpm store 位置，避免换 store 后重装整个依赖。

### 阶段 2 起：后端需要 MySQL

- Mac：Docker Desktop，`pnpm db:up` / `pnpm db:down`。
- Windows：不用 Docker，用免安装版 MySQL 8.4（ZIP 解压到 `C:\Data\mysql`，同目录放 `my.ini`：端口 3307、只监听 127.0.0.1、utf8mb4）。放在别处时先 `set PD_MYSQL_DIR=目录`。不注册 Windows 服务，电脑重启后要重新 start：

  ```bat
  tools\env\mysql.cmd start     :: 第一次会初始化 C:\Data\mysql\data，并执行 tools\env\mysql-init.sql 建库建账号
  tools\env\mysql.cmd status
  tools\env\mysql.cmd stop
  ```

  端口、库（`pd` / `pd_shadow` / `pd_test`）、账号密码都和 `docker-compose.yml` 一致，`apps/server/.env.example` 的连接串不用改。日志在 `C:\Data\mysql\data\<计算机名>.err`。
  - 坑：mysqld 会把 `my.ini` 里和完整路径里的中文读成乱码（最初装在 `C:\Data\Project\环境\mysql` 时踩到），所以 MySQL 不放在 `环境` 里，而是放纯英文路径 `C:\Data\mysql`；脚本仍进到该目录后用相对路径启动，作为保险。
- `apps/server/.env` 不入库，每台各自从 `.env.example` 复制，`JWT_SECRET` 要换成随机值（示例值会被拒绝）。

## 2. 每次换电脑的固定步骤

1. **开工前**：`git pull`。拉下来的提交改了 `pnpm-lock.yaml` 或某个 `package.json` 时，再运行 `pnpm install`；新增了 `apps/server/prisma/migrations/` 下的迁移时，运行 `pnpm --filter @pd/server db:deploy`。
2. **收工前**：提交并 `git push`，另一台才能拿到。没写完也可以先提交，在提交说明里写明「未完成」。
3. 两台不要同时改同一处。真的冲突了，按正常的 git 合并处理，不要强推。

## 3. 不同步的东西（每台电脑各自一份）

| 内容 | 位置 | 说明 |
|---|---|---|
| 依赖 | `node_modules/` | 每台各自 `pnpm install`，不能拷贝 |
| MARD 色值 | `packages/palettes/data/local/mard-hex.json` | 不入库（许可原因）；新电脑运行 `pnpm palettes:sync` 下载一次；两台目前都已有 |
| 色卡数据 | `packages/palettes/data/palettes.json` | `pnpm install` 时自动生成 |
| 评测输出 | `tools/bench/out/` | `pnpm bench` 生成 |
| 竞品截图 | `tools/bench/competitors/` | 不入库，只在当时做对比的那台电脑上 |
| 后端数据库 | Mac：docker 卷 `pd_pd-mysql`；Windows：`C:\Data\mysql\data` | 每台各自一份；要跨电脑看到作品，登录同一账号需要连同一个后端（阶段 2 只在本机跑，所以两台的账号互不相通） |
| 上传的图片 | `apps/server/storage/` | 不入库 |
| 网页里的「我的作品」 | 浏览器 IndexedDB | 按电脑、浏览器、网址各存一份；无痕窗口关闭后会清空 |

## 4. 换行符和文件名

- 根目录 `.gitattributes` 规定仓库里一律存 LF（`.cmd` / `.bat` / `.ps1` 除外，存 CRLF），所以 Windows 上的 `core.autocrlf` 设置不会再造成整文件换行符变化。
- 第三方原样数据（`packages/palettes/vendor/`、`tools/bench/images/manifest.csv`）保持原来的 CRLF，不转换。
- 中文文件名两边都能正常用；在 Mac 上 `git status` 里中文显示成 `\350…` 转义只是显示问题，可以用 `git -c core.quotepath=false status` 看。
