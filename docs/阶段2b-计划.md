# 阶段 2b 计划：小程序接入账号与云同步

> 2026-11-07 起草，**待用户确认**。前置：阶段 2（网页账号与云端）已验收，1b 小程序已完成到 1b-6（导出色号清晰度待真机复核）。

## 1. 目标

小程序里登录后，作品自动存到云端；同一个账号在网页上登录能看到、能接着改，反过来也一样。不登录照常能用（作品只存在手机上）。

只在本机跑（后端、MySQL 都在这台电脑），不部署、不花钱。

## 2. 现状

| 已有 | 说明 |
|---|---|
| 后端 `POST /api/auth/wx-login` | 用 `wx.login()` 的 code 换 openid；第一次用自动建一个「拼豆用户」账号。需要 `.env` 里填 `WX_APPID` / `WX_SECRET` |
| 作品接口 | `PUT /api/works/:id`（带 baseRevision，版本不符 409）、`GET /api/works?since=`、软删除、历史版本、图片上传 `POST /api/files`（直接发图片字节） |
| 网页同步 `apps/web/src/cloud.ts` | 本机为主、保存后 2 秒同步；冲突另存「（冲突副本）」；别处删除但本机有修改时另存「（已在别处删除）」。和网页的界面、存储写在一起，不能直接给小程序用 |
| 小程序作品 `apps/miniapp/src/lib/works.ts` | 本地 JSON + 原图 + 缩略图，草稿格式和网页相同（`PatternDraftV1`），所以云端数据两边可以直接互相打开 |

**缺口**：微信账号和网页的「用户名 + 密码」账号是两个不同的账号，现在没办法互通。

## 3. 账号互通方案（推荐）

| 方式 | 做法 |
|---|---|
| 微信一键登录 | 小程序「我的」页点一下登录（`wx.login`），第一次自动建账号 |
| 小程序里用网页账号登录 | 输入网页的用户名和密码登录；登录后可以「绑定微信」，以后直接一键登录这个账号 |
| 微信账号去网页登录 | 在小程序里给微信账号「设置网页登录的用户名和密码」，之后网页用这个用户名登录 |

后端要新增：
- `POST /api/me/wx-bind { code }`：把当前微信绑到已登录的账号。如果这个微信已经有一个**空的**微信账号（没有作品），就把那个空账号删掉再绑；如果那个微信账号里有作品，拒绝并提示（不自动合并，避免弄乱数据）。
- `PUT /api/me/credentials { username, password }`：只给还没有密码的账号（微信建的）设置用户名和密码。
- 接口测试覆盖上面的情况。

不做：网页「微信扫码登录」（要微信开放平台的网站应用，需要企业资质和费用）。

## 4. 同步做法

- 新增 `packages/app-shared/src/sync.ts`：**和平台无关的同步引擎**。规则和网页完全一致（本机为主、baseRevision 乐观并发、冲突副本、已在别处删除、游标往前多取 10 秒），只依赖两个接口：「本地作品存取」和「接口请求」。全部用单测覆盖（假的本地存储 + 假的服务端）。
- 小程序实现这两个接口：`wx.request`（令牌刷新、401 处理）、`WorksStore` 增加作品归属（哪个账号）、云端版本号、是否有未同步修改、原图在云端的文件名。原图用 `wx.request` 发图片字节上传，用 `wx.downloadFile`（带令牌）下载。
- 什么时候同步：保存后 2 秒、打开小程序 / 回到前台、进「我的作品」时。
- 登录时如果手机上有未登录时做的作品，询问「存到账号里吗」（和网页一样）。退出登录后，账号的作品在手机上隐藏。
- 「我的作品」每个作品显示同步状态（已同步 / 待同步 / 离线）。
- 网页的 `cloud.ts` **这一阶段不改**（已验收，改它有回归风险）；以后再考虑让网页也换用共享引擎。

## 5. 页面

- 首页加「我的」入口（或在「我的作品」顶部）：未登录显示「微信一键登录」「用网页账号登录」；已登录显示昵称、同步状态、绑定微信 / 设置网页密码、退出登录。
- 登录前要勾选同意用户协议和隐私政策（草案，和网页同一份）。
- 历史版本（网页已有）：本阶段小程序先不做，放后面。
