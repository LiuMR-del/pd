## 1. 项目目标

做一个面向拼豆爱好者的轻量工具：**上传图片 → 生成带色号的拼豆图纸 → 编辑 → 导出/分享**。
定位参照「今天拼豆了吗」（pindoule.cn）：工具为主、不做社区与商城，后期靠「豆豆」虚拟币变现。
功能和算法思路参考竞品（豆格、今天拼豆了吗），**代码、素材、品牌全部自研**，不调用、不抓取竞品接口。

## 2. 主体与平台

### 2.1 主体：推荐个体工商户

| 主体 | 微信支付 / 虚拟支付 | 限制 | 结论 |

| 个人 | 可开通个人虚拟支付（据官方文档摘要：月限额 10 万元） | 类目少；不能做 UGC 社区；不能卖实物 | 能起步，但天花板低 |

| 平台 | 结论 | 理由 |

## 4. 算法：竞品对比与我们的方案

### 4.1 竞品算法对比（基于前端代码静态分析，未实跑出图对比）

两家的普通「图片→图纸」都在**前端 Canvas** 完成，后端只负责 AI 改图、保存、计费。

| 环节 | 豆格 | 今天拼豆了吗 | 更优 |
|---|---|---|---|
| 输入分辨率 | 长边缩到 **300px** 再采样（网格 >100 时每格仅 2~3 像素） | 长边缩到 **1024px**，高质量平滑 | 今天拼豆了吗 |
| 网格形状 | 强制正方形，非方图留空白外框 | 按原图宽高比；能检测原图像素周期（适配像素图/AI 图） | 今天拼豆了吗 |
| 单格取色 | 块内像素逐个匹配色号后加权投票；中心色亮度差大时优先中心（保细线） | 三种方案：边缘投票（暗线优先，保描线）/区域平均/逐点匹配投票 | 接近，今天拼豆了吗方案更多 |
| **色号匹配公式** | `0.7×加权RGB欧氏距离 + 0.3×HSL距离`（已确认），非感知色差；灰色/低饱和色色相不稳定，易错配 | **CIEDE2000**（感知色差标准）/ CIE76 Lab | **今天拼豆了吗明显更优** |
| 限色 | Lab 空间贪心选色，权重 count^0.65，2~40 色 | Lab 三步贪心合并（相近合并→稀有色并入→强制合并），保护暗色 | 今天拼豆了吗 |
| 去杂色 | 4 邻域 ≥3 同色则替换；连通区域合并 | 小孤岛降噪、短线恢复、轮廓断口闭合、肤色噪点清理 | 今天拼豆了吗 |
| 去背景 | 删除边缘出现最多的那一个色号（渐变背景/主体触边时易误删） | 从边缘洪泛近白像素 + 自动裁边 | 今天拼豆了吗 |
| 抖动 | 无 | 无 | 都没有 |
| 色板 | 服务端下发，品牌/色数分档多（Mard、优肯、小舞、黄豆豆、DODO、CoCo…） | 以 MARD 291 为主表，其他品牌按 MARD 色值映射（非实测，可能偏色） | 豆格（数据更全） |
| 预设 | 省豆简化 48格/16色、均衡 72/24、细节优先 100/36 | 粒度 80、16 色默认；easy/balanced/rich | 豆格预设更易懂 |
| AI 模式 | 后端 AI 出像素画 → 前端 7×7 高斯采样 + CIEDE2000 | 后端出 768² Q 版图（人像/宠物等 6 类）→ 前端精确采样 | 都依赖服务端模型 |

**结论：今天拼豆了吗的转换算法整体更优**，核心差距在三点：CIEDE2000 色号匹配、高分辨率输入、针对描线/背景的后处理。豆格的优点是**品牌色卡数据全**和**预设文案清晰**。
两家共同短板：无抖动（照片渐变出色带）、限色只按频率取舍（瞳孔高光等小面积显著色易被吞）、平均/投票在 sRGB 而非线性光空间进行。

> 该结论来自代码阅读，未做同图实测。阶段 0 会用测试集做量化对比后再定稿。

### 4.2 我们的算法方案（取两家之长 + 补共同短板）

管线（纯 TypeScript 包 `@pd/pattern-core`，小程序 Worker / H5 / Node 测试共用）：

1. **输入**：在**线性 RGB** 空间按面积覆盖做区域平均，直接下采样到 `列 × k` × `行 × k`，避免糊边和偏暗。（v0.4：原为「先缩放到长边 × 8」，改为一步到位；v0.5：默认 k=1，即每格取线性光平均，细节交给第 3 步的细笔画保护）
2. **网格**：按宽高比确定；长边颗数可选（预设 + 自定义 10~200）；像素图/AI 图模式做周期检测对齐原生格子。
3. **单格取色**：每格 k×k 子采样点 → 各自匹配色号 → 中心加权投票；暗线保护（暗像素占比超阈值时优先暗色；v0.4 起还要求周围以浅色为主、且紧贴浅色格）；平坦区退化为均值。（v0.5 起默认 k=1：每格直接取线性光平均，投票和暗线保护不再起作用，仅在手动设 k>1 时生效；卡通预设另加**边缘归并**：格内 3×3 子采样色差 ≥40、且平均色落在两侧邻格颜色连线上的硬边格，归到更接近的一侧，消除浅色过渡圈。）v0.5 新增**细笔画保护**：在每格最多 8×8 的细网格上做形态学 top-hat，找出比一格还细的深线 / 浅线（覆盖 ≥10%、对比 ≥25 L*），周围 7×7 格以背景色为主、且不是密集纹理时，用笔画核心颜色覆盖该格。
4. **色号匹配**：感知色差最近色。**阶段 0 定稿（v0.4）：CIEDE2000，先用 Oklab 预筛 8 个候选再精排**；纯 Oklab 保留为低端机 / 实时预览的降级选项。只在用户选定的品牌 + 色数档（如 MARD 72 色）内匹配；色板色值预计算 + 缓存。
5. **限色**：候选色在 Lab 空间做加权聚类合并（贪心 + 一轮 k-means 精修），加**显著性保护**：高饱和/高对比的小色块与暗线不被吞并。
6. **抖动（可选）**：Lab 空间误差扩散，强度 0~100%，**默认关**（抖动会制造大量零散单颗，难拼）；「照片模式」默认开低强度。
7. **后处理**：孤立点清理（8 邻域众数）、少于 N 颗的色块并入最近色、去背景（边缘洪泛 + 颜色容差，不只认一种颜色；v0.4 起只从足够长的边缘连续段起步，避免误删触边的主体）、自动裁边；**空格不填豆**。v0.5 起去背景后会按主体外框重新生成一次，让主体撑满用户选的长边（fitSubject，耗时约翻倍）。
8. **预设**：卡通（描线保护强、无抖动）/ 照片（抖动低强度、肤色平滑）/ 像素图（周期对齐、不做平滑），外加省豆、均衡、细节三档尺寸。
9. **输出**：网格（色号索引）+ 用量统计 + 预览渲染数据。

### 4.3 效果验证方法（阶段 0 交付）

- 测试集约 20 张：卡通、人像、宠物、风景、文字、像素图、AI 图。
- 量化指标：平均 ΔE00（图纸 vs 原图下采样）、用色数、孤立单颗占比、背景误删率。v0.4 补充：ΔE00 偏向 CIEDE2000、ΔEok 偏向 Oklab，所以另加 CAM16-UCS 色差作为中立裁判；另加暗线召回率和耗时。结果见 `docs/阶段0-算法报告.md`。
- 人工评审：同一张图并排对比 我们 / 豆格 / 今天拼豆了吗 的输出（竞品输出由你手动在其工具里生成截图，我们不自动调用竞品服务）。

### 8.2 它的算法水平与我们的改进

| 环节 | perler-beads 现状 | 我们的处理 |
|---|---|---|
| 色差 | Oklab 欧氏距离（感知均匀，优于豆格，和 CIEDE2000 接近且更快） | 保留，阶段 0 与 CIEDE2000 实测对比。**v0.4 已定稿**：CIEDE2000 + Oklab 预筛 8 个候选，纯 Oklab 作为降级选项 |
| 主色采样 | 统计**精确 RGB 值**出现次数取最多：卡通图有效；照片噪点多时几乎每个像素都不同，退化成取首个像素 | 改为「子采样点先匹配色号再投票」+ 暗线保护 |
| 均值采样 | sRGB 空间直接平均 | 改为线性 RGB 平均 |
| 限色 | 相似度阈值合并 + 手动排除颜色，**无颜色数上限** | 增加颜色数上限 + 显著色保护 |
| 去背景 | 边界洪泛 | 保留，增加颜色容差 + 自动裁边 |
| 抖动 / 去孤立点 | 无 | 新增（抖动默认关） |
