### 四、运行方法

```bash
pnpm install                 # 也会生成色卡数据和 Prisma 客户端
pnpm db:up                   # docker 启动 MySQL（127.0.0.1:3307），首次会建 pd / pd_shadow / pd_test 三个库
cp apps/server/.env.example apps/server/.env    # 首次
pnpm --filter @pd/server db:deploy              # 首次：建表
pnpm dev:server              # 后端 http://127.0.0.1:3100/api/health
pnpm dev:web                 # 网页 http://localhost:5173（/api 代理到 3100）
pnpm dev:admin               # 后台 http://localhost:5174（先用 admin:create 建管理员）
pnpm -r test                 # 全部单测；apps/server 的测试需要 MySQL 已启动
pnpm -r typecheck
```

### 五、必须遵守的约定

- 计划、说明、总结用简体中文；代码、命令、标识符保持英文。
- 每完成一小步就提交并 `git push`，任务清单写明进度；提交说明末尾加 `Co-Authored-By` 行（按你所用工具的规则）。
- **AGPL-3.0**：源自 perler-beads 的代码和数据只放在 `packages/pattern-core`、`packages/palettes`；新第三方代码在 README 注明许可。MARD 色值不入库（`pnpm palettes:sync` 每台电脑下载）。
- Nest 依赖注入一律写显式 `@Inject(...)`（项目不开 emitDecoratorMetadata，tsx / vitest / esbuild 才能直接跑）。
- 接口错误统一 `{ error: { code, message } }`，message 是给用户看的中文。
- Prisma 在 AI 执行 `migrate reset` 等破坏性命令时会要求用户明确同意：**不要伪造同意、不要绕过**。改表用 `pnpm --filter @pd/server db:migrate`（`prisma migrate dev --name xxx`）；测试库只 `migrate deploy`，测试数据用唯一名字，不清库。
- 依赖版本：pnpm 有新版本冷却期，只选发布超过约一周的版本；新的安装脚本要在 `pnpm-workspace.yaml` 的 `allowBuilds` 里显式放行。
- 不做未授权的：删除数据、部署上线、发消息、付费操作。阶段 2 只在本机运行，不部署。
- 端到端测试脚本放会话临时目录，不入库。
