### 3. 实现算法管线（方案 4.2 节，逐步实现并配单测）

输入输出约定：
- 输入：`{ data: Uint8ClampedArray(RGBA), width, height }`，加上选项。
- 不依赖 Canvas 和 DOM，必须能在微信小程序 Worker 里运行。

管线步骤：
1. 色彩基础：sRGB ↔ 线性 RGB ↔ Lab / Oklab；实现 CIEDE2000，用 Sharma 2005 论文的标准测试数据做单测；色板色值预计算加缓存。
2. 网格：按宽高比确定行列；长边颗数 10~200；在线性 RGB 空间做区域平均下采样；像素图模式做周期检测（可以放到最后做）。
3. 单格取色：每格取 k×k 个子采样点，各自先匹配色号，再按中心加权投票；加暗线保护。参考思路：暗像素（亮度 < 45）占比超过约 0.3 时优先取暗色；阈值做成可调参数。
4. 色差：`distance` 做成可插拔，实现 `oklab` 和 `ciede2000` 两种。
5. 限色：颜色数上限 2~60；在 Lab 空间做加权聚类合并（贪心合并后再精修一轮）；显著色保护：高饱和或高对比的小色块、暗线不能被吞并。
6. 抖动：Lab 误差扩散，强度 0~1，默认 0。
7. 后处理：
   - 孤立点清理（8 邻域众数）；
   - 少于 N 颗的色块并入最近色；
   - 去背景：边缘洪泛 + 颜色容差；
   - 自动裁边；
   - 空格标记为空，不填豆。
8. 预设：
   - 风格三种：卡通、照片、像素图；
   - 尺寸三档：省豆 48 格 / 16 色、均衡 72 / 24、细节 100 / 36；
   - 品牌和色数档：比如 MARD 72 色。
9. 输出：`{ cols, rows, cells: Uint16Array(色板索引，空格用 0xFFFF), palette, stats: [{key, hex, count}], timings }`。

另外，把 perler-beads 原版的 dominant / average 管线保留为 **baseline**，作为对比基线。

### 4. 测试集和评测（`tools/bench`）
- **真实图已备好**：`tools/bench/images/` 下有 22 张 PNG，分 7 类，许可证均为 CC BY。先读同目录的 `README.md` 和 `manifest.csv`。
  - 测试图片已按用户要求随公开仓库提交；对外展示或分发时须按 `manifest.csv` 署名。
  - 另外用程序生成合成测试图，放在 `tools/bench/synthetic/`：色块、渐变、细线、文字、带白底的主体、无缩放的小尺寸像素点阵图。合成图用来计算背景误删率，也补上真实图缺的像素图原图。
- 图片解码只在 bench 里用 `sharp` 或 `pngjs`，作为 devDependency。
- 指标：
  - 平均 ΔE00：图纸和原图下采样结果对比；
  - 用色数；
  - 孤立单颗占比；
  - 合成图上的背景误删率；
  - 耗时：100×100 网格、72 色，桌面 Node 上目标 < 1s。
- 对比组：baseline、我们 + Oklab、我们 + CIEDE2000，每组都在卡通、照片两个预设下跑。
- 输出预览 PNG 到 `tools/bench/out/`，再做一个本地静态对比页，同图并排看各组结果。
- 竞品输出只由我手动截图放进 `tools/bench/competitors/`，相关 PNG 和 JSON 已随公开仓库提交。**禁止调用或抓取豆格、今天拼豆了吗的任何接口。**
