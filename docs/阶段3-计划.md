## 2. 文字转图纸

**输入**：文字（可多行）；字高（每行几格，6~60，默认 16）；粗体；对齐（左 / 中 / 右）；字间距、行间距（格）；文字颜色（从当前品牌色数档里选）；描边（无 / 1 格，可选颜色）；背景（无 = 空格不放豆 / 选一种颜色）；四周留边（格）。

**做法**：
- 平台层只负责「把文字画到一张透明画布上，交回像素」：网页用 OffscreenCanvas / canvas，小程序用 `wx.createOffscreenCanvas`。字体用系统字体（与导出图同一组：苹方 / 微软雅黑 / Noto Sans SC），不打包字体文件，小程序主包不受影响。
- 共享层（新包 `@pd/makers`）：按字高 × 4 倍超采样画字，再按每格覆盖率（默认 ≥ 45%）判断这格放不放豆；描边是在文字外圈膨胀 1 格；最后整理成网格和色板。
- 总尺寸超过 200 格时提示缩小字高或减少字数。

**限制**：系统字体在很小的字高下会糊，中文字高建议 ≥ 12 格，英文和数字 ≥ 7 格（界面给提示）。不同电脑 / 手机的系统字体不同，同一段文字在 Mac、Windows、手机上画出来会略有差异；保存后的图纸是格子本身，不会再变。像素字体（小字更清楚）要额外打包字体文件，本次不做。

## 3. 二维码转图纸

**输入**：网址或任意文字；纠错等级（L / M / Q / H，默认 M）；深色、浅色（默认当前品牌最接近黑、白的色号）；静区（二维码四周的空白，默认 4 格，可选 2~4）；浅色和静区是否放豆（默认放；放在白色豆板上时可以不放，省豆）。

**做法**：
- 编码器：引入 Project Nayuki 的 QR Code generator（TypeScript 版，**MIT 许可**，单文件，业界常用的参考实现），按 perler-beads 的做法在文件头注明来源、commit 和许可，放在 `@pd/makers` 里。不加运行时 npm 依赖。
- 一个模块 = 一颗豆。自动选最小版本；总尺寸（含静区）超过 200 格时提示内容太长。
- **「保证能扫」怎么保证**：
  1. 深浅色对比度不够时（亮度对比低于设定阈值）不让生成，并提示换色；不允许深浅反色。
  2. 单测里用 jsQR（**Apache-2.0**，只作开发依赖，不进产品）把生成的图纸渲染成图片再解码，覆盖各纠错等级、长短内容、中文、各种深浅色组合、静区 2 / 4 格，必须解出原文。
  3. 编辑器里改了二维码图纸后，导出前不再保证能扫（界面提示）。
- **上传二维码图片**（例如自己的微信二维码）：网页端识别图片里的二维码内容，再重新生成干净的图纸。识别用 jsQR，按需加载（只在点这个功能时才下载，约 40KB 压缩后）；小程序端以后用微信自带的 `wx.scanCode`（可以从相册选图），不用打包 jsQR。小程序码（圆形的太阳码）不是二维码，识别不了，界面说明。

## 4. 品牌转换

**输入**：已有图纸；目标品牌（MARD / COCO / 漫漫 / 盼盼 / 咪小窝）和色数档。

**做法**（放在 `@pd/editor-core`）：
- 图纸里每个色号先找到色卡里对应的颜色，再取目标品牌的色号；目标色数档里没有这个颜色时，在目标色数档内按 CIEDE2000 找最接近的色。
- 应用前先给一张对照表：原色号 → 新色号、颗数、「同色」或「近似（色差 x.x）」，近似的排在前面，用户确认后再换。
- 转换是一步编辑，可以撤销；图纸记录的品牌和色数档同步改掉，用量和导出都按新色号。

**已知数据局限**（沿用方案第 7 节）：除 MARD 外，其他品牌的色值来自 perler-beads 的映射表，是按 MARD 色值对应的，不是实测；所以「同色」只表示映射表里是同一行。界面在非 MARD 品牌旁注明「色值为对应参考，非实测」。

## 5. 网页界面改动

- 首页「选择图片」旁加两个入口：**文字** / **二维码**。
- 右侧设置面板（手机是参数抽屉）按图纸来源切换内容：图片 → 现有参数；文字 → 第 2 节的参数；二维码 → 第 3 节的参数。都是「改参数 → 重新生成」，有手工修改时照旧先确认并自动备份。
- 「我的作品」保存图纸来源（图片 / 文字 / 二维码）和对应参数，打开后能继续改参数重新生成；以前保存的作品按「图片」处理，不受影响。
- 用量面板加「换品牌」按钮，打开第 4 节的对照表对话框。

## 8. 实施结果（2026-11-04）

- `@pd/makers` 单测 45 个（二维码 32：L/M/Q/H × 长短内容、中文、版本 40、静区 2/3/4、浅色不放豆、四组彩色配色，全部用 jsQR 解出原文；文字 12；ES2015 打包检查 1）；`@pd/editor-core` 新增品牌转换单测 8 个。全仓单测 195 个通过，类型检查通过。
- 端到端（Playwright，脚本不入库）28 项全部通过：桌面 1280×800 文字（预览、选描边色、生成、改参数重新生成、导出）、换品牌（对照表、换成 COCO、设置跟着变、撤销恢复 MARD、重做后重新生成仍是同样的豆子）、二维码（尺寸和对比度提示、生成、导出、同色被拒、上传识别）、刷新后从作品恢复文字 / 二维码及其参数（换过品牌的作品仍是新品牌）、图片流程回归；手机 390×844 文字 / 二维码 / 换品牌；页面零报错。
- 发现：导出的二维码图纸 PNG（带网格线和坐标）用 jsQR 按原尺寸解不出；不印色号时缩小到 1/2 能解出；格子里印色号时（如 COCO 的 B09）缩小后也解不出。图纸是照着拼的说明，网格线和色号只在纸面上，拼出来的豆子没有，单测按豆子渲染全部能扫；拼好后仍建议先用手机扫一下确认。
- 提交前代码审查（独立审查代理）：3 个阻断问题已修——①文字 / 二维码的颜色原来按色号保存，换品牌后同一个色号在新品牌里是另一种颜色 → 改为按色卡颜色编号保存，换品牌后自动对应（目标色数档没有时取最接近的色）；②换品牌没写进作品保存的参数，重新打开后按旧品牌重新生成会悄悄丢掉转换 → 打开作品时以图纸自身的品牌 / 色数档为准，换品牌时同步写入；③换品牌或撤销后画笔颜色还指向旧品牌的豆子 → 换品牌时画笔颜色跟着换，撤销 / 重做时不在当前品牌里就重置。另修：识别二维码图片期间切换作品，结果会写进别的作品（加作品会话检查）；文字的描边和背景选同一种豆子时用量表出现两行（合并）；品牌转换先按色值认颜色、色值不同不算同色；行尾空格不再撑宽图纸；预览改用 shallowRef。
- 遗留（1a 起就有）：重新打开有手工修改的作品后，`edited` 为 false，重新生成不会提示备份。建议以后在草稿里保存「有手工修改」标记。
- 顺手修复：设置面板底部「生成图纸」按钮下方会露出一条被滚动的内容（sticky 只停在滚动容器的内边距处）。
